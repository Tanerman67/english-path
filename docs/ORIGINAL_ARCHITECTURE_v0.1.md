# English Path — архитектура и MVP v0.1

**Статус:** проектное решение и первые 7 структурированных уроков. Приложение ещё не реализовано, аудиозаписи не созданы.

## 1. Продукт

Отдельное mobile-first web-приложение для практического B1→B2, ориентированное на повседневную речь в Новой Зеландии и рабочие ситуации (в том числе IT-интеграции и управление задачами). Русский язык объяснений и перевода; английский — основной язык упражнений. Курс не должен утверждать, что несколько уроков подтверждают уровень CEFR.

### Цель MVP

Пользователь может открыть урок, изучить правило и словарь, ответить на автоматические упражнения, выполнить speaking/writing с самопроверкой, получить очередь повторений, закрыть приложение и продолжить без потери прогресса. Доступны экспорт и импорт локальных данных.

### Не входит в MVP

Авторизация, облачная синхронизация, AI, распознавание речи, автоматическое оценивание свободного ответа, оплата, подписки, сертификат CEFR, социальные функции, сложная адаптивность. Новые уроки после первых семи — отдельный этап.

## 2. Рекомендуемый стек

- React + TypeScript + Vite: статический frontend.
- React hooks/context и простой маршрутизатор; не добавлять тяжёлое управление состоянием преждевременно.
- CSS с мобильным дизайном, доступность клавиатуры и скринридеров.
- IndexedDB + Dexie: данные пользователя (progress, attempts, review schedule, settings).
- JSON content packs с неизменяемыми ID, ревизиями и валидацией контента.
- Vitest (логика) + Playwright (пользовательские сценарии).
- Статический хостинг по HTTPS; PWA/offline caching — после стабилизации базовой функциональности либо частью релизного этапа, если это простое добавление.

Источники: https://vite.dev/guide/build ; https://dexie.org/docs/API-Reference ; https://dexie.org/docs/ExportImport/dexie-export-import ; https://www.coe.int/en/web/common-european-framework-reference-languages/cefr-descriptors

## 3. Техническая схема

```text
React UI
├── Home
├── Learn: lesson player + interactive exercises
├── Review: scheduled retrieval
├── Library: browse/search content
└── Progress: completed lessons, review stats

├── answer checker for deterministic question types
```

## 4. Схема контента

Каждый урок в `content/lessons/Lnnn.json` имеет стабильные поля: `id`, `revision`, `moduleId`, `order`, `title`, `level`, `goalRu`, `grammar`, `vocabulary`, `phrases`, `dialogue`, `listening`, `exercises`, `reviewItemIds`. У всех слов, фраз и упражнений стабильные ID. Ревизию увеличивают при изменении содержания, не переиспользуя ID для другой учебной единицы.

Поддерживаемые типы упражнения v0.1:

- `single_choice`: проверка выбранного точного значения `correct`.
- `fill_blank`: сверка со списком допустимых ответов `acceptedAnswers` после нормализации пробелов, регистра и конечной пунктуации; не подменять семантическую оценку строгим сравнением.
- `self_assessed_speaking`: произнести ответ вслух, затем отметить честный чек-лист.
- `self_assessed_writing`: написать ответ и сравнить с моделью, не выдавая автоматическую экспертную оценку.

Аудио: `listening.audioAsset` = null в текущих данных. Сценарии для озвучивания уже есть в `dialogue`, но аудиофайлы необходимо создать/проверить отдельно. До появления аудиофайла не показывать кнопку «Play audio» как работающую.

## 5. Хранение прогресса

Рекомендуемые IndexedDB-таблицы:

| Таблица | Пример основных полей | Задача |
|---|---|---|
| `lessonProgress` | lessonId, status, startedAt, completedAt, revisionSeen | Продолжить урок |
| `exerciseAttempts` | attemptId, exerciseId, lessonId, answer, correct?, createdAt | История ответов |
| `reviewItems` | itemId, sourceLessonId, nextReviewLocalDate, intervalStep, lastOutcome | Повторения |
| `settings` | key, value | Язык интерфейса, настройки |
| `appMeta` | schemaVersion, contentPackVersion | Обновления и совместимость |

Не привязывать сохранённый прогресс только к индексу элемента в массиве: порядок уроков может измениться. Не хранить учебный контент и пользовательские ответы в одной таблице.

### Экспорт / импорт

- Экспортируемый JSON: `formatVersion`, `exportedAt`, `lessonProgress`, `exerciseAttempts`, `reviewItems`, `settings`.
- Предварительно валидировать импорт, показать количество записей и предупредить о конфликтах.
- Режим по умолчанию — осторожное объединение по стабильным ID, без удаления существующего.
- Перезапись только после явного подтверждения и предложения создать резервную копию.
- При изменении схемы использовать миграции. Тестировать обновление со старой базы.

Важно: IndexedDB может быть очищена браузером. Для первого релиза необходим явный экспорт резервной копии и понятная инструкция по восстановлению.

## 6. Экран урока — последовательность

1. Цель (1 мин)
2. Объяснение правила с 2 примерами (4–5 мин)
3. Восемь новых слов, пять готовых фраз (7 мин)
4. Короткий диалог и аудирование, **после появления аудио** (5 мин)
5. Автопроверяемые упражнения: 2 выбора + 2 пропуска (5–7 мин)
6. Speaking без подсказки + самопроверка (5 мин)
7. Writing + сравнение с примером (5–7 мин)
8. Итог и постановка фраз в очередь повторения (1 мин)

Это ориентиры нагрузки, а не таймеры и не требование уложить всех пользователей в одинаковое время.

## 7. План первого модуля

| Урок | Тема | Grammar | Итоговая способность |
|---|---|---|---|
| L001 | Introducing yourself at work | Present Simple/Continuous | Обязанности и текущие задачи |
| L002 | Talking about progress | Present Perfect/Past Simple | Краткое сообщение о прогрессе |
| L003 | Talking about ongoing work | Perfect vs Perfect Continuous | Продолжительность работы |
| L004 | Clarifying requirements | Indirect questions | Уточнение требований |
| L005 | Explaining a technical problem | Past Simple/Continuous, linkers | Объяснение проблемы |
| L006 | Suggesting solutions | Modals + first conditional | Обсуждение вариантов |
| L007 | Real work conversation | Integrated review | Сквозной диалог и follow-up |

Каждый JSON включает грамматику, восемь слов, пять фраз с переводами, диалог, упражнения с ответами, speaking prompt, writing prompt и образец, вопрос на аудирование. Всего 56 слов и 35 целевых фраз в первом модуле. Многие конструкции — повторы и активизация уже знакомого материала, а не 91 полностью новая единица.

## 8. Повторение

На старте: после завершения урока карточку планировать на следующие локальные календарные дни: +1, +3, +7. Если ответ неправильный или пользователь нажал «Не помню» — вернуть на завтра. Если пользователь пропустил день, просроченные карточки остаются в очереди; не подменять прогресс из-за пропуска. Не считать самооценку speaking/writing объективным подтверждением владения языком.

Для MVP хранить `nextReviewLocalDate` как локальную дату YYYY-MM-DD без смешения с UTC. Повторение карточки не должно каждый раз создавать её дубликат.

## 9. Матрица покрытия шести навыков

| Навык | Как появляется в каждом уроке | Механизм MVP |
|---|---|---|
| Grammar | Основная конструкция и примеры | Rule + quiz |
| Vocabulary | 8 слов и 5 chunks | Cards + retrieval |
| Speaking | Один открытый устный сценарий | Prompt + self-check |
| Listening | Диалог + comprehension question | Script; audio after recording |
| Writing | Короткое текстовое задание | Draft + model + self-check |
| Work English | Контекст диалога / задачи | Scenarios and practical language |

Проверку B2 нужно проектировать отдельно на основе CEFR can-do descriptors; прохождение 7 уроков само по себе не означает уровень B2.

## 10. Критерии готовности MVP

- [ ] Все 7 уроков открываются и отображают корректные примеры и переводы.
- [ ] Ответы на закрытые задания проверяются с объяснением.
- [ ] Свободные ответы не получают выдуманных оценок и не отправляются в облако.
- [ ] Урок можно прервать и продолжить после перезапуска приложения.
- [ ] Сохранение не теряется при обновлении контента и схемы базы (тест миграции).
- [ ] Review показывает правильно назначенные и просроченные элементы без дубликатов.
- [ ] Экспорт создаёт файл; импорт восстанавливает тестовый профиль (проверка round-trip).
- [ ] Дизайн удобен на экранах смартфона и с клавиатуры.
- [ ] Приложение ясно показывает, какие функции доступны только с интернетом.
- [ ] Для настоящего listening все 7 аудиофайлов созданы, вычитаны и протестированы, либо соответствующая функция честно отмечена как ещё не готовая.
- [ ] Нет секретов, пользовательских данных и ключей в публичном репозитории.

## 11. Рекомендуемый порядок реализации

1. Создать репозиторий, TypeScript/Vite/React, типы данных и валидатор JSON.
2. Реализовать один полный сквозной урок L001 и сохранение его прогресса.
3. Добавить движок упражнений и независимые тесты правильных/неправильных ответов.
4. Подключить L002–L007 без дублирования компонентов.
5. Добавить review scheduler, библиотеку и простой progress.
6. Сделать экспорт/импорт и тесты миграций до публикации.
7. Подготовить проверенные аудиофайлы и связать их с `audioAsset`.
8. Провести контент-ревью на естественность фраз и отображение на телефоне.

**Следующая отдельная фаза:** остальные темы B1→B2, расширение банка упражнений, аудио с разными акцентами, более совершенный алгоритм повторений. AI-собеседник только после стабильного core flow.
